# Geoapify and driver locations

Geoapify is the default address-search and road-routing provider. Create a free project at https://myprojects.geoapify.com/ and set `GEOAPIFY_API_KEY` and `ROUTING_PROVIDER=geoapify` in `.environment/.env`. Run `python scripts/sync_env.py` with the backend venv from the repository root, then restart local servers. Hosted Render settings are separate. Never expose this key through `NEXT_PUBLIC_` variables.

`backend/app/services/geoapify.py` implements India-filtered geocoding and metric driving-route estimates. API errors and missing routes fail explicitly; straight-line distance never substitutes for a verified road route. The same adapter is used by passenger matching and automatic maintenance. Google remains an explicit optional adapter (`ROUTING_PROVIDER=google`); it is not an automatic fallback.

Address search is submitted explicitly, rather than sending a request on every keystroke. Provider responses have a five-minute, 256-entry process cache. Concurrent cache misses are serialized with at least 260 ms between requests. Existing authenticated per-user hourly budgets apply to search/matching. The rate limiter is process-local: introduce a shared limiter before running multiple API workers/replicas. No unlimited quota or automatic paid upgrade is promised. Watch the Geoapify dashboard; credits differ from requests and rides, particularly for long routes. Free use requires Geoapify/data-source attribution, included on the passenger form.

The driver taps **Share my location** on an assigned or started trip. HTTPS browser geolocation requests permission only after that tap. It obtains a fresh, high-accuracy position every 15 seconds while the page is visible and sends it to `PUT /ride-groups/{id}/driver-location`. This path makes no mapping-provider call. Only the assigned driver can update/delete the pin; the existing authenticated group-read policy limits visibility to trip members, its driver and operators. The database stores only the latest coordinate, accuracy and timestamps, not a movement history.

Passengers see the coordinate accuracy, age, and **View driver in Google Maps / Get directions** buttons. Locations older than 60 seconds are marked stale and navigation links are withheld. Google Maps URLs require no API key and open a snapshot, not a moving marker. `DELETE /ride-groups/{id}/driver-location` clears the saved coordinate; trip completion/cancellation also clears it. Sending invalid, old, out-of-order or too-frequent positions is rejected.

Sharing stops on component removal and tries to clear the saved pin after pending uploads finish. A browser close, lost connection, locked phone or switching apps can prevent updates/deletion. Old coordinates become stale; the page cannot guarantee background GPS tracking. Keep the driver page open and obtain a fresh pin before navigation. A native app is needed for a reliable background-tracking experience. Location precision depends on the device and surroundings; local airport pickup accuracy needs field testing.

Migration `database/migrations/202610110005_driver_location.sql` must precede deployment. `/ready` checks the selected provider key and new database columns, but does not make paid/provider calls or certify key validity.

Sources: [routing](https://apidocs.geoapify.com/docs/routing/), [geocoding](https://apidocs.geoapify.com/docs/geocoding/), [free plan and attribution](https://www.geoapify.com/pricing/), [Google Maps URLs](https://developers.google.com/maps/documentation/urls/get-started), [browser geolocation](https://developer.mozilla.org/en-US/docs/Web/API/Geolocation/getCurrentPosition).

Verification: synthetic adapter, lifecycle/access-control and frontend permission/link tests; a real public Aluva address search returned two results and a sample airport-to-Aluva route returned 19,593 m / 1,506 s. These calls validate connectivity and response parsing, not field accuracy. Human driver/passenger permission and movement testing remains required.
